AI Transcriber is a self-hosted transcription service that runs entirely on your own machine:

- **Transcription** with [faster-whisper](https://github.com/SYSTRAN/faster-whisper) (CPU/GPU) or [WhisperX](https://github.com/m-bain/whisperX) (word-level alignment + optional speaker diarization).
- **Summaries** generated by any OpenAI-compatible LLM server (tested with [LM Studio](https://lmstudio.ai/)).
- **Delivery** to Bitrix24 as a smart-process item with the transcript attached.
- **Two front-ends**: a rich terminal CLI and a browser Web UI with a job queue and live progress.

No cloud, no API keys for transcription — everything is local. A Hugging Face token is only needed for the optional diarization models.

## How it works

```text
Audio / Video
   -> WhisperX ASR (faster-whisper)          transcribe
   -> Word-level alignment                   always on (WhisperX)
   -> Speaker diarization                    optional
   -> Transcript (.txt / .json)
   -> LLM summary (.md)                      optional
   -> Bitrix24 smart-process item            optional
```

Existing `.txt` transcripts skip transcription and go straight to summary/send.

## Requirements

| Requirement | Notes |
|---|---|
| **Python** 3.12 or 3.13 | 3.13 recommended (`.python-version` ships 3.13) |
| **FFmpeg** (`ffmpeg`, `ffprobe`) | in `PATH`; Windows: set `FFMPEG_DLL_PATH` (see below) |
| **RAM** | 16 GB recommended; long files and `large-v3` need more |
| **Disk** | ~10–20 GB free for model downloads |
| **Hugging Face token** | only for the WhisperX backend / diarization (optional) |
| **LM Studio** | only for summaries (optional, any OpenAI-compatible server works) |

> Hardware is auto-detected at startup: NVIDIA **CUDA** > Apple Silicon **MPS** > **CPU**. You can pin a device explicitly (see [Device & compute type](#device--compute-type)).

## Installation

### 1. Clone the repository

```bash
git clone <your-repo-url> ai-transcriber
cd ai-transcriber
```

### 2. Create a virtual environment

**With [uv](https://docs.astral.sh/uv/) (recommended):**

```bash
uv venv
uv sync --extra test
```

> `uv sync` respects the pinned `torch==2.8.0` and, on Windows x64, pulls the CUDA 12.8 build automatically via the `pytorch-cu128` index defined in `pyproject.toml`.

**With plain `venv` + `pip`:**

```bash
python3.13 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -e .
```

Windows scripts are also provided in [`scripts/`](scripts): `setup_cpu.ps1` and `setup_gpu.ps1`. The CPU script installs CPU torch wheels after syncing; a subsequent plain `uv sync` restores the configured Windows CUDA source, so rerun the CPU script when updating that environment.

### 3. Install FFmpeg

- **macOS:** `brew install ffmpeg`
- **Linux:** `sudo apt install ffmpeg` (or your distro's package)
- **Windows:** download from <https://www.gyan.dev/ffmpeg/builds/> and either add `bin` to `PATH` or set:

  ```bash
  FFMPEG_DLL_PATH=C:\ffmpeg\bin
  ```

### 4. Configure environment (optional but recommended)

Copy the template and fill in the values you need:

```bash
cp .env.example .env
```

See [Configuration](#configuration) for every variable.

### 5. Verify the installation

```bash
ai-transcriber doctor
```

All checks (Python, FFmpeg, faster-whisper, LM Studio) should be green. The LM Studio check will fail until you start LM Studio — that is fine if you don't use summaries.

## Configuration

All settings live in a `.env` file in the project root (loaded automatically). `.env` is **git-ignored** — never commit it.

| Variable | Required | Default                        | Purpose |
|---|---|--------------------------------|---|
| `HF_TOKEN` | for WhisperX | —                              | Hugging Face token. Enables the WhisperX backend and speaker diarization. |
| `WEBHOOK_IT_TASK` | for presets | —                              | Bitrix24 webhook shown as the *it_task* preset in the Web UI. |
| `WEBHOOK_HR` | for presets | —                              | Bitrix24 webhook for the *hr* preset. |
| `WEBHOOK_CALL_TRACK` | for presets | —                              | Bitrix24 webhook for the *call_track* preset. |
| `OPENAI_API_KEY` | — | `lm-studio`                    | Passed to the LLM endpoint (LM Studio ignores it; use for real OpenAI-compatible services). |
| `FFMPEG_DLL_PATH` | Windows | `C:\ffmpeg7\bin`               | Directory containing `ffmpeg.exe` DLLs. |
| `MPS_LONG_FILE_THRESHOLD_SECONDS` | — | `600`                          | In `auto` mode, files longer than this fall back to CPU on Apple Silicon (see below). |
| `LLAMA_PORT` | — | `1234`                         | Port for the bundled llama.cpp fallback server. |
| `LLAMA_CTX` | — | `8192`                        | Context window for the bundled LLM. |
| `LLAMA_MODEL_REPO` | — | `unsloth/Qwen3-4B-Instruct-2507-GGUF`      | Hugging Face repo with the fallback GGUF model. |
| `LLAMA_MODEL_FILE` | — | `Qwen3-4B-Instruct-2507-Q4_K_M.gguf`       | GGUF file to download (~2.5 GB). |
| `LLAMA_NGPU` | — | `99` (accelerator) / `0` (CPU) | GPU layers offloaded by llama.cpp. |
| `LLAMA_CACHE_DIR` | — | `~/.cache/ai-transcriber`      | Where llama.cpp binaries and the GGUF model are stored. |

### About the webhook variables

The **Web UI** picks endpoints from `WEBHOOK_IT_TASK`, `WEBHOOK_HR` and `WEBHOOK_CALL_TRACK` and shows them in a dropdown. You can also type any webhook URL manually in the UI.

The **CLI** `--send it_task|hr|call_track` option uses the corresponding `WEBHOOK_*` environment variable. Direct exporter calls can use `WEBHOOK_URL` as a fallback. Preset URLs remain on the server; the browser receives preset names.

## Quick start

```bash
# 1. Run environment checks
ai-transcriber doctor

# 2. Transcribe an audio/video file (auto language detection)
ai-transcriber transcribe meeting.mp4

# 3. Transcribe + summarize a meeting (requires LM Studio on :1234)
ai-transcriber transcribe call.mp3 --prompt meeting --summary

# 4. Start the Web UI
ai-transcriber web
# -> http://127.0.0.1:8000
```

The CLI writes `transcript.json` and `transcript.txt` next to the source file, and `SUMMARY_OF_*.md` when summarization is enabled.

## CLI reference

### `ai-transcriber transcribe FILE`

| Option | Short | Default | Description |
|---|---|---|---|
| `--model` | `-m` | `large-v3-turbo` | Whisper model (see [Models](#models)). |
| `--prompt` | `-p` | `meeting` | Summary prompt type: `meeting` or `call`. |
| `--language` | `-l` | auto | Language code, e.g. `ru`, `en`. Omit for auto-detect. |
| `--output` | `-o` | next to source | Base path for the `.txt` and `.json` outputs. |
| `--normalize` | `-n` | off | Normalize volume (`loudnorm`, 16 kHz mono) before transcription. |
| `--compute-type` | `-ct` | `auto` | `auto`, `int8`, `int8_float32`, `float16` or `float32`. |
| `--summary` | `-sum` | off | Generate an LLM summary. |
| `--llm` | — | interactive | LLM model id for the summary; skips the interactive selection. |
| `--send` | `-send` | — | Send to Bitrix24: `it_task`, `hr` or `call_track` (uses the matching `WEBHOOK_*` variable; requires `--summary`). |
| `--gpu` | `-g` | off | Request CUDA explicitly; otherwise hardware is auto-detected. |

### What you can do

- **Upload** audio, video or an existing transcript (`.txt`, `.md`, `.log`).
- **Transcribe**: model, backend (auto / WhisperX / faster-whisper), device (auto / CPU / CPU+MPS / CUDA), language, compute type, audio normalization.
- **Summarize**: prompt type (meeting / call / custom), custom prompt, LLM endpoint and model.
- **Send**: pick a preset webhook or type a URL manually.
- **Track** jobs live: progress, step, logs, and download the transcript/summary when done.

### Behaviour notes

- UI state is persisted to `data/web_config.json` and restored on the next visit.
- Tasks run **serially** (one at a time) — parallel pipelines would exhaust memory on 16 GB machines.
- Jobs run one at a time, with at most 20 active/queued jobs; a full queue returns HTTP 429. Cleanup retains active jobs and the latest five uploads/output directories.
- `faster-whisper` backend: diarization is always skipped (a warning is shown if you enable it).
- Sending to a webhook **requires** the summary step to be enabled (the summary text is part of the created Bitrix item).
- If the configured LLM endpoint is unreachable, the bundled **llama.cpp + Qwen3-4B-Instruct-2507** server is started automatically for the summary (no extra config).

### Where files go

```text
data/
  web_config.json     # persisted UI configuration
  web_uploads/        # uploaded source files
  web_outputs/<job>/
      <name>.txt      # transcript
      <name>.json     # word-level transcript
      SUMMARY_OF_<name>.md
```

| Endpoint | Purpose |

## Models

The default model is `large-v3-turbo` — the recommended choice: near-`large-v3` accuracy at roughly 8× lower compute.

| Model | Params | When to use |
|---|---|---|
| `tiny` | 39M | Smoke tests, very low RAM. |
| `base` | 74M | Quick drafts, noisy/noisy short clips. |
| `small` | 244M | Good accuracy / speed trade-off. |
| `medium` | 769M | Better accuracy, more RAM needed. |
| `large-v3` | 1550M | Best accuracy; heavy (needs a strong machine). |
| `large-v3-turbo` | ~809M | **Default.** Best accuracy-per-cost, recommended. |

Notes:

- Models are downloaded **once** on first use into the Hugging Face cache (`~/.cache/huggingface`) and then reused.
- Transcribing in a specific language (`--language ru`) is faster and more accurate than auto-detect.
- On a 16 GB machine, stick to `large-v3-turbo` with `int8`; reserve `large-v3` for CPU/CUDA machines with plenty of memory.

## Device & compute type

The **Web UI** exposes a `Device` dropdown; values shown depend on your hardware.

| Choice | ASR | Alignment / diarization | Compute |
|---|---|---|---|
| `auto` | best available | best available | int8 / float16 |
| `cpu` | CPU | CPU | int8 |
| `mps` (CPU + MPS, macOS only) | CPU | Apple Silicon MPS | int8 |
| `cuda` (NVIDIA only) | CUDA | CUDA | float16 |

**Compute types:** `int8` (fastest, least memory) → `int8_float32` → `float16` → `float32` (slowest, most memory). Lower = faster on most hardware.

### Apple Silicon (MPS) memory management

MPS uses the Mac's **unified memory**, which is shared with the OS — long files easily exhaust it. To keep things stable:

- Models are loaded **one at a time** and released (with `gc.collect()` + `torch.mps.empty_cache()`) between stages: ASR → alignment → diarization.
- Tasks are serialized so two pipelines never run at once.
- In `auto` mode, files longer than `MPS_LONG_FILE_THRESHOLD_SECONDS` (default **600 s = 10 min**) automatically run on CPU instead of MPS to avoid OOM. Set the variable to `0` to disable the fallback, or pick **CPU + MPS explicitly** in the UI if you want MPS regardless of file length.
- Diarization is off by default in the Web UI; enable it only for short files on MPS.

## Backends: WhisperX vs faster-whisper

| | WhisperX | faster-whisper |
|---|---|---|
| Word-level alignment | ✅ | ❌ |
| Speaker diarization | ✅ (needs `HF_TOKEN`) | ❌ |
| Requires `HF_TOKEN` | ✅ | ❌ |
| Best for | Timed transcripts, speakers, long files | Simple, fast, low-memory transcription |

`backend: auto` picks **WhisperX** when `HF_TOKEN` is set, otherwise **faster-whisper**.

### Getting the Hugging Face token

1. Create an account at <https://huggingface.co>.
2. Accept the terms for the gated diarization model: <https://huggingface.co/pyannote/speaker-diarization-3.1>.
3. Create a read token at <https://huggingface.co/settings/tokens> and set it as `HF_TOKEN` in `.env`.

## Summaries (LLM)

Summaries go through any **OpenAI-compatible** chat endpoint. The default is LM Studio at `http://localhost:1234/v1`.

### Interactive model selection (CLI)

Both `transcribe --summary` and `summarize` ask for the LLM model at the keyboard:

1. The service queries the endpoint and prints the list of loaded models.
2. You type the number of the model you want and press Enter (Enter alone picks the first one).

```text
┌─── Available LLM models ───┐
│ # │ Model                   │
│ 1 │ qwen/qwen3.5-9b         │
│ 2 │ deepseek-r1-distill-... │
└───┴─────────────────────────┘
Select LLM model number (Enter = first): 1
```

Pass `--llm <model-id>` to skip the prompt (useful for scripts):

```bash
ai-transcriber summarize meeting.txt --llm qwen/qwen3.5-9b
```

### Bundled fallback (no LM Studio)

If LM Studio is not running (or the endpoint is unreachable), the CLI **and the Web UI** **automatically**:

1. Download the llama.cpp prebuilt binary for your platform (GitHub releases).
2. Download **Qwen3-4B-Instruct-2507** GGUF (`Qwen3-4B-Instruct-2507-Q4_K_M.gguf`, ~2.5 GB) from Hugging Face.
3. Start `llama-server` locally with a **context window selected by the RAM policy** and use it as the endpoint.

Both downloads happen once and are cached in `LLAMA_CACHE_DIR` (`~/.cache/ai-transcriber`). Downloads can be overridden with `LLAMA_MODEL_REPO`, `LLAMA_MODEL_FILE`, `LLAMA_PORT`, `LLAMA_CTX`, `LLAMA_NGPU` (see the [Configuration table](#configuration)).

In the Web UI the shared server is reused across jobs while the configured endpoint stays down, and is stopped (memory + port freed) as soon as the regular endpoint answers again. No extra settings are needed — just enable **Summary**.

### Setup

1. Install [LM Studio](https://lmstudio.ai/), open the **Local Server** tab, load a model and press *Start Server*.
2. In the Web UI, leave *LLM model* empty to use the first model served, or pick one from the autocomplete list (fetched from `GET {endpoint}/models`).
3. Choose a prompt type:
   - **meeting** — structured meeting summary;
   - **call** — call-style summary;
   - **custom** — your own template. Use `{text}` inside it as the placeholder for the transcript, e.g.:

     ```
     Тезисно перескажи на русском: {text}
     ```

> If no LLM server is available, transcription still works — only the summary step would fail, and instead both the CLI and the Web UI automatically fall back to the bundled Qwen3-4B-Instruct-2507 via llama.cpp.

## Sending to Bitrix24

The send action creates a **Bitrix24 smart-process item** and attaches the transcript file as a timeline comment:

1. `crm.item.add.json` — creates the item with the entity, category and custom fields configured in `.env`.
2. `crm.timeline.comment.add.json` — attaches the `.txt` transcript as a comment.

The endpoint is a Bitrix24 REST webhook:

```text
https://your-portal.bitrix24.ru/rest/<user_id>/<token>/
```

- **Web UI:** set `WEBHOOK_IT_TASK` / `WEBHOOK_HR` / `WEBHOOK_CALL_TRACK` in `.env` (dropdown presets) or paste any URL manually. Enable **Send** — it requires **Summary** to be on.
- **CLI:** `ai-transcriber transcribe file.mp3 --summary --send it_task`.

Configure the portal schema in `.env`; source edits are unnecessary:

```dotenv
BITRIX_ENTITY_TYPE_ID=0
BITRIX_CATEGORY_ID=0
BITRIX_STAGE_ID=
BITRIX_ASSIGNEE_IDS=[]
BITRIX_FIELDS_JSON={}
```

Replace `0` with your portal's entity/category IDs. Map custom fields to
`"summary"`, `"assignees"`, `"executor"`, or a literal value using
`BITRIX_FIELDS_JSON` (see `.env.example`). No portal identifiers are bundled.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `MPS backend out of memory` | Use `auto`/`cpu` for long files, keep diarization off, set `MPS_LONG_FILE_THRESHOLD_SECONDS`, or pick **CPU + MPS** only for short files. |
| WhisperX backend error / diarization skips silently | `HF_TOKEN` missing or terms not accepted for `pyannote/speaker-diarization-3.1`. |
| `ffmpeg` / `ffprobe` not found | Install FFmpeg or set `FFMPEG_DLL_PATH` (Windows). |
| Summary step fails | Start LM Studio (or point `LLM endpoint` at your own OpenAI-compatible server). |
| `torchcodec is not installed correctly` warning | Harmless; audio is decoded by FFmpeg instead. |
| Diarization checkbox has no effect | The `faster-whisper` backend does not support diarization — switch backend to WhisperX. |
| CUDA not used | Install the CUDA build of torch (Windows `uv sync` does this automatically); pick `cuda` device. |
| Web UI keeps old settings | Configuration persists in `data/web_config.json` — delete it to reset. |
| Send fails with Bitrix error | Verify the webhook token/URL and that summary is enabled; check field IDs in `webhook_exporter.py`. |

## Security

- `.env` contains **secrets** (HF token, webhook tokens). It is git-ignored — keep it that way.
- The whole service runs locally; don't expose the Web UI to the public internet without auth.
- Rotate HF/webhook/API credentials if they have been published or shared.
- Activate the local secret check after cloning: `git config core.hooksPath .githooks`.
- Run `python3 scripts/check_secrets.py` to scan staged files, or add `--history HEAD` to scan reachable history. The check rejects environment/private-key files and common token formats without printing their values. GitHub Actions also runs it; it is a heuristic, so review diffs before publishing.
- Preset webhook secrets stay server-side. `data/web_config.json` never contains webhook URLs. Manual URLs are used for the current job only; put reusable URLs in `.env` (`WEBHOOK_CUSTOM` or the other presets). Preferences are created with owner-only permissions on POSIX.
- Browser requests from foreign origins are rejected. The Web UI still has no user authentication; keep it on a trusted network.
